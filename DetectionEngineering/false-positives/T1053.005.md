# False-Positive Analysis — T1053.005

## Objective

Evaluate whether the scheduled-task Sigma rule flags legitimate scheduled-task creation.

## Detection Rule

* Rule: `T1053.005_scheduled_task.yml`
* Rule title: Scheduled Task Created Using Schtasks
* Detection condition: `schtasks.exe` with `/create` in its command line
* MITRE ATT&CK: T1053.005 — Scheduled Task

## Benign Test Scenario

A harmless scheduled task named `BenignDetectionTest` was created using Windows Task Scheduler command-line utility `schtasks.exe`.

The task action was:

`cmd.exe /c exit 0`

The task was configured to run once at a specified time. The action was designed to exit without performing any additional operation.

## Telemetry

* Source: Windows Sysmon
* Event ID: 1 — Process Creation
* Evidence file: `Sysmon_BenignTest.evtx`
* Evidence location: `C:\DetectionEngineering\logs\T1053.005_Scheduled_Task\Sysmon_BenignTest.evtx`

Three process-creation events were identified for `BenignDetectionTest`, corresponding to repeated task-creation attempts.

## Result

Chainsaw reported four detections when applying the scheduled-task Sigma rule to the exported EVTX file. The Sysmon evidence confirms that the rule's matching conditions occur during the benign task-creation activity.

Because the rule detects `schtasks.exe` with `/create` without distinguishing legitimate from suspicious task creation, it is broad and may produce false positives.

The four Chainsaw detections must not all be attributed to the benign task without checking each matching event individually.

## Conclusion

The initial rule detects the targeted task-creation behavior, but its broad condition can also match legitimate administrative activity. This identifies a potential false-positive issue and a need for further testing and tuning.

## Future Work

1. Test additional legitimate scheduled-task creation scenarios.
2. Review the context and command line of each matching event.
3. Develop and validate a tuned rule that reduces false positives without losing detection of the Atomic Red Team test.
4. Retest the original Atomic Red Team scenario and the benign scenario after tuning.
## Rule Tuning and Comparative Results

### Objective

Evaluate whether a more specific Sigma rule can reduce alerts on the tested benign activity while preserving detection of the selected Atomic Red Team behavior.

### Results

| Test scenario                  | Original rule                 | Tuned rule   |
| ------------------------------ | ----------------------------- | ------------ |
| Atomic Red Team T1053.005 test | Previously recorded detection | 1 detection  |
| BenignDetectionTest            | 3 detections                  | 0 detections |

### Analysis

The original rule detects `schtasks.exe` when its command line contains `/create`. It matched the three process-creation events generated during repeated attempts to create the benign task.

The tuned rule additionally requires a logon trigger and `wscript.exe` in the command line. It detected the selected Atomic Red Team test but produced no detections against the isolated benign-test evidence.

### Conclusion

In the test scenarios evaluated, the tuned rule was more selective than the original rule. It retained detection of the selected Atomic Red Team behavior and did not alert on the tested benign task.

These results are limited to
 the specific Atomic and benign scenarios examined. Additional tests are needed to evaluate general detection coverage and false-positive behavior.
